04 / METRICS

要与 App01 对账的指标词典

正向销量 / 退货件数

正 units 求和；负 units 的绝对值求和。退货率 = 退货件数 ÷ 正向销量。

避免把负销量输入需求预测。
净销售额 / 销售成本 / 毛利

对同一范围内的 signed net_sales、cogs 求和；毛利 = 净销售额 − 销售成本。

沿用源数据金额单位，不虚构币种。
已知在手 / 已知库存成本

仅聚合有效库存项；成本 = 已知在手 × 有效单位成本，缺成本项目不填零。

同时显示成本覆盖率与分母。
数据覆盖与时效

截至 2026-04-24；显示 SKU、门店、库存有效项与有交易行日期数。

“有记录日”不等于抽取完整率。
对账检查比较方式通过条件
观察窗口Power BI 与 App01 同设 2026-03-28—04-24、大类/产品线/SKU/门店范围样本日期与筛选实体完全一致。
销售与退货正向销量、退货件数、净销售额和 cogs 对照 App01 的观测指标按一致的数据有效性规则逐项相等；差异列出具体 SKU 与原始行。
库存覆盖核对每个 SKU × 门店的已知/未知状态与单位成本来源未知项可见；有效期记录不被当作日盘点。
事实与情景分离逐页审核标题、KPI 标记和下载字段PSI 未满足、提议量、服务目标不出现在“已发生”页。
05 / DELIVERY

macOS 制作顺序与验收门槛

优先使用浏览器中的 Power BI Service：先准备 Excel 多表工作簿，再于 My workspace 建语义模型、关系、DAX 和报表。只有网页功能或账号限制确实挡住目标时，才考虑 Windows 远程环境。Power BI MCP 不是前置条件。

M0 / DATA PACKAGE

冻结源数据

生成工作簿、转换脚本、字段词典、筛选说明及 SHA-256。

验收：

行数、键、观测 28 天指标与 App01 对账；无伪造交期/在途。

M1 / SEMANTIC MODEL

网页端建模

My workspace → New → Semantic model → Excel；建立星型关系与基础 DAX。

验收：

筛选无重复计数；库存不会随销售日期出现错误变化。

M2 / REPORT QA

制作与校验两页

完成主 KPI、趋势、矩阵、异常表、筛选与钻取。

验收：

大类至 SKU 可追查；空值、负结果与数据限制可见。

M3 / PORTFOLIO

封装案例

导出页面截图、指标词典、模型图、对账记录及对照说明。

验收：

无账号的招聘方也能看懂；链接分享按许可单独确认。
