06B+ 方案：一个应用覆盖两个缺口

#4 需求预测 + #7 库存优化 · 合并而不是并列做两个

为什么合并

两个缺口的短板恰好互补：#4 缺实时层、像统计玩具；#7 数据就绪度只有 6.5、卡在 ERP 主数据质量。预测给库存提供可复现的上游误差分布，库存给预测提供业务重量与现金流出口。单独做预测＝工具；单独做库存＝依赖用户 ERP 且无法验证；串起来＝决策链。版块账上，一个应用覆盖两个缺口，「从研究到产品」从 1/7 走到 3/7。

一句话定位：把「预测准不准」推进到「库存该备多少」，起点是你自己那个诚实的负结果。

四层数据架构

L1
用户自带层 · 上传 CSV
日期 × SKU × 销量，浏览器内解析，不上传服务器。这层的价值是「你的数据、你的结论」，天然规避造数嫌疑。
L2
真实结论层 · 你的 pilot
AI hybrid MAPE 16.68% vs Naive lag-7 baseline 12.42%。这是本应用最强的差异化资产，也是唯一的「非造数」起点。
L3
决策层 · 纯确定性计算
误差分布 → 服务水平 z 值 → 安全库存 → 补货点 → 库存占用与持有成本。全部公式可审查、结果可在浏览器内复现。
L4
演示层 · UCI Online Retail II CC BY 4.0 · 已下载解析
已替换 Favorita 并完成落盘解析（详见第 07 节）：1,067,371 行 → 4,985 SKU → 67% 为间歇型需求，正是 Croston 的主场。注意它是单渠道、无多级结构——英国的单一在线批发商，因此多级库存（缺口 #7）只能由合成层承担，这条已上升为硬约束。构建期切片后内置。

功能模块

  • 模型擂台：Naive / 季节性 Naive / 移动平均 / 指数平滑 / Croston / 轻量 GBDT——全部纯 JS 可行（Prophet 依赖 Stan，排除）。
  • 误差 → 库存传导：把 4.26 个百分点的 MAPE 差距换算成安全库存与现金占用的差额。这是全站最有说服力的一张图，也是那个负结果第一次变成业务语言。
  • 牛鞭效应：沿层级放大，呼应雷达「热门议题」栏。
  • 诚实徽章：模型未超越 baseline 时显式披露，并给出差距分析。

红线（与 TariffLens 同等级别，不可回退）

  • ① 不输出「最优库存」或「建议下单量」。只输出「给定服务水平与误差分布下的参考安全库存区间」，并明列公式与假设。
  • ② 所有模型在浏览器内可复现。不拿预计算结果冒充实时运算——本站批评过这种包装。
  • ③ 不冒充实时层。页面明示「用户自带数据 + 公开月度宏观序列」，不写「实时」二字。
  • ④ 不引入 LLM。与 A 同一口径：本站的可信资产是「可审查的确定性逻辑」，不是 LLM 包装。

间歇型（覆盖率 <30%）3,11667%Croston / SBA

覆盖率分位：p10 = 0.03 · p25 = 0.07 · 中位 = 0.18 · p75 = 0.38 · p90 = 0.58。也就是说中位 SKU 每 5.5 天才出一次货。这正是 sales = 0 泛滥、MAPE 会退化失效的经典场景，也正是 Naive / MA 这类方法会被 Croston 显著拉开差距的地方——「多模型擂台」在这份数据上比在 Favorita 上更有戏。

抽样还显示典型的块状需求（lumpy demand）：间歇组某 SKU 前 30 天为 [288, 305, 9, 31, 0, 0, 11, 0, 14, 0, …]——批发客户一次性提货，而非零星出货。这是库存管理最难的一档，恰好落在本公司缺口 #7 的射程里。

代价条款（新增硬约束，须逐条接受）

换 UCI 不是无痛的。它解决了许可问题，但掏走了多级结构：

  • UCI 是单渠道、单主体数据——一家面向英国市场的在线礼品批发商，SKU 层级之上没有仓库/门店层级。而 Favorita 天生就是 54 家店 × 33 个品类。
  • Country 维度顶替不了层级。实测：United Kingdom 占 82.5% 销量（9,634,240 单位 / 4,974 SKU / 604 活跃天），其余 42 个国家销量中位数仅 7,038 单位，丹麦只有 41 个活跃天、澳大利亚 77 天——序列稀疏到做不了任何独立建模。用它冒充「多级」是自欺。
  • 因此：缺口 #7「多级库存 / 防呆」demo 的唯一来源必须是合成层。这把 L4 里那条合成序列从「锦上添花的演示」提升为承重墙——它要负责 DC → RDC → 前置仓的三级结构、牛鞭效应演示、以及多级安全库存的正确算法（不是各点独立算再相加）。这是本轮改动对实施计划影响最大的一条。
  • 顺带记住：UCI 缺 onpromotion，促销扰动因子改由合成层提供，或改用「星期几 + 月度季节性」作为可解释变量。

这该如何落到实施上

  • 构建期脚本（新增 M0 任务）：下载 zip → read_only 解析 xlsx → 按 SKU 统一 str 化、显式剔除 Quantity ≤ 0 行 → 聚合成 SKU × 日 → 按覆盖率分箱挑选序列 → 输出≤200 KB 的 demo-series.json。脚本可放进 B+ 独立仓库，作品集只引用产物。
  • 页面标注（不可省）：来源 UCI Online Retail II（UCI ML Repository #502），CC BY 4.0；聚合口径：剔除退货与冲销行，单位＝日销量（件）；数据区间 2009-12-01–2011-12-09。必须写明年份，不能让访客误以为是实时数据。
  • 合成层接管范围：多级（DC/RDC/前置仓）、牛鞭效应、促销扰动、控制变量的方法对照实验。全部标注 [SYNTHETIC]。

这对评分的影响

B+ 的数据就绪度从 7.0 上调到 7.5：现在有了免密钥 + CORS 的真实公开数据层（/rows 抽样）与许可干净的基准集（UCI），不再是纯「用户上传」。但它仍然不是实时层——数据是历史零售数据，页面必须写明年份与来源，一个字不能含糊。

重算：9.0×0.28 + 8.0×0.20 + 7.5×0.16 + 7.0×0.16 + 9.5×0.20 = 2.52 + 1.60 + 1.20 + 1.12 + 1.90 = 8.34。与 A 的 8.40 仍是实质并列，排序不变。
