03推荐 A · 异常处置编排台

Candidate A · 对应缺口 #5 多智能体异常处置编排（7.8 分，业务价值 9.5 全榜最高）

#54 个已验证实时源与既有应用零重叠

DisruptionOps · 供应链扰动处置编排台

一句话定位：把「一票延误、跨部门调查三天」压成一张可执行事件卡——真实扰动事件 × 你的供应节点，自动匹配取证链与处置剧本，并给出 SLA 倒计时。

它解决的到底是哪件真事

缺口 #5 的原文是：「一票延误的跨部门调查动辄三天，把『事件 → 取证 → 评估 → 执行』交给协作智能体，可将处置压缩到小时级。」这句话里最痛的不是「不知道出了事」，而是取证散落在邮件里、判定标准在少数人脑子里、每个人都在等别人的结论。DisruptionOps 不做决策替身，它做三件机械但昂贵的事：把事件发生的第一手官方链接钉住、把受影响节点算出来、把该走的动作清单列成可勾选的表格。

三层数据架构

L1
实时层 · 全局扰动事件流 免密钥 · CORS 全开 · 已实测
GDACS（含官方红/橙/绿分级 + 影响区多边形）+ NASA EONET + USGS 地震 + NOAA NWS 警报。四源合并去重后落入统一事件 schema，每条事件必附官方原文 URL（这是取证链的锚点）。
L2
节点层 · 你的供应地图 用户自带 · 不出本机
上传/粘贴工厂、仓库、港口、关键供应商清单（名称 + 坐标 + 品类 + 关键度），存 localStorage，不上服务器。内置一份标注 [DEMO] 的示例节点集，保证首屏可用。这层是「真数据」，也是把全局天气新闻变成「与我有关」的唯一开关。
L3
编排层 · 剧本库 确定性规则 · 本地执行
按灾种/中断类型组织的处置剧本（热带气旋 / 地震海啸 / 洪水 / 港口或园区中断），每条动作含责任岗位、建议时限、所需证据。由规则引擎选择，非 LLM 生成——见下方红线。

功能模块

  • 扰动事件流：时间轴 + 分级色标（沿用 GDACS alertlevel，不自创分级）；按是否命中你的节点分「全局 / 与我有关」两栏。
  • 影响命中算版：点在多边形判定（GDACS 影响区）× 半径衰减（USGS/NWS 用震级与距离）× 节点关键度 → 合成一张「受影响资产清单」。算法全部写在页面上，参数可调，不隐藏。
  • 事件卡：一屏给出——发生了什么（官方原文链接）／影响哪些节点／严重度评分与它的计算过程／处置清单（勾选即留痕）／SLA 倒计时。
  • 取证链导出：把事件、命中判定、动作勾选记录导出为一份 JSON / CSV，可直接贴进事后复盘与保险索赔材料。这是「闭环」真正落地的地方。
  • 口径面板：与 DemoDataBanner 同构，逐块标注数据来源、抓取时间、哪个源失败了。

三条红线（不可回退，等同 TariffLens 的口径红线）

  • ① 不调用 LLM。纯静态站没有、也不该有 API 密钥。编排 = 确定性 pipeline（分类 → 命中 → 严重度 → 剧本匹配），页面上必须写明「编排规则本地执行，不含 LLM 生成」；把 LLM 叙事列为「需授权 · 付费」层。遵守这条反而成为本站最强的可信资产——市面上 90% 的「多智能体」demo 都在装。
  • ② 节点数据不出本机。不上传、不写远程存储。
  • ③ 数据源失败必须显式降级。任一源超时/报错就显示「该源当前不可用，最近成功抓取 X」，绝不用缓存旧值冒充实时；四源全挂时不显示「当前无事件」，而是显示「无法获取，不可判定」。

04推荐 B · 需求预测方法学擂台

Candidate B · 对应缺口 #4（7.8 分）· round 1 曾被判「暂行候审」，本次以新证据重估

#4无 SKU 级实时源真实 pilot 在手独门负结果

ForecastArena · 需求预测方法学擂台

一句话定位：把你手上的 pilot 变成可复现的实验台——上传 CSV，浏览器里真跑 baseline 与自研模型，并把「AI 到底有没有打过 naive」如实摆出来，包括你现在输的那 4 个百分点。

两处对 round 1 评估的修正

  • 「浏览器跑不了真模型」——部分不成立。round 1 的顾虑集中在 Prophet / LSTM。但需求预测真正用得上的主力为：Naive lag-7 / 季节 Naive / 移动平均 / Holt-Winters / Croston（间歇需求）/ 自研轻量 GBDT 回归。前五个纯 JS 无任何问题；GBDT 是自写 CART + boosting（约 250 行），几千行样本级训练在浏览器里是秒级。这不等于 Prophet 能跑（依赖 Stan/CmdStan，应明确排除），但「模型层面的 AI 含量」已从「统计玩具」升级为「真训练」。
  • 「无公开实时源」——半成立。实测 Eurostat 可用且当日更新（月度序列）、世界银行 CORS 全开（年度）。虽仍然没有 SKU 级实时数据，但可以给应用补上一层真实宏观/行业序列作为开箱即用的公开基准样例，不必只靠用户上传。

三层数据架构

L1
真实序列层 · 公开宏观/行业 免密钥 · 已实测
Eurostat 月度工业生产 / 外部贸易（updated 2026-09-29）+ 世界银行集装箱吞吐量等。用于「打开就有真东西可跑」与教学对照。明确标注其为宏观序列，不等于 SKU 需求。
L2
用户自带层 · 上传 CSV 真数据 · 不出本机
日期 × SKU × 销量，浏览器内解析。这是「你的数据、你的结论」，天然规避造数嫌疑。
L3
结果层 · 你的 pilot 负结果，忠于原值
AI hybrid MAPE 16.68% vs Naive lag-7 baseline 12.42%——落后约 4 个百分点。作为内置案例，公开它的失败方式与差距归因。

功能模块

  • 滚动原点评估：不用单一 holdout，按时间序列多折滚动原点切分，避免「靠一个幸运期」，这是 pilot 结论最容易站不住的地方。
  • 擂台表：MAPE / MAE / RMSE + 偏差（bias）分列——只看 accuracy 不看 bias 会漏掉系统性少预测，而后者才是缺货与呆滞的成因。
  • 未超越 baseline 徽章：当任何模型输给 seasonal naive，显式显示「模型未超越 baseline · 差距 X pp」，并给出归因检查清单（样本长度 / 季节性长度 / 间歇性占比 / 离群 / 节假日特征缺失 / 数据泄露嫌疑）。这是本应用最强的差异化点，也是市面上几乎没人敢展示的东西。
  • 牛鞭效应演示：呼应雷达「热门议题」栏，展示误差沿层级的放大。
  • 下游延伸（可选）：把预测误差映射到安全库存与营运资金占用——顺带接住缺口 #7 的一半。
为什么它排第二：准入标准第 2 条仍然只是「半满足」——宏观序列不是 SKU 需求，SKU 层依然依赖用户自带；且「多模型视角」的叙事已被 5 份报告充分表达过。但它握着两个别的候选都没有的东西：你本人的真实工作经历，以及一个诚实的负结果。这两样加起来，恰好是本站「口径守门人」人设最锋利的一次落刀。

结论：先做 A（DisruptionOps），B（ForecastArena）紧跟

决定性因素依然是准入标准第 2 条。A 是唯一拿到「多个免密钥 + CORS 全开 + 当日有真数据」实时源的候选；实测 GDACS 当天就挂着一条红色气旋警报，意味着上线首屏就有真实内容，无需任何演示数据撑场。

第二个决定性因素是叙事空间。缺口 #5 的业务价值是全榜并列最高（9.5，与 #1 并列），而「多智能体编排」恰恰是最容易注水、也最容易做实的题目：不接 LLM 密钥，把编排写成可审查的确定性规则，反而在一堆「AI Agent 演示」里显出分量。

B 不该无限期排队。它缺的实时层已被 Eurostat 补上一半，而你手上的 pilot 与那个负结果是有保质期的资产——越早落成工具，越能在它还代表你当前工作水平的时候发挥作用。建议 A 上线后立即启动 B，两者的工作量结构也不冲突（A 是数据接入 + 规则引擎，B 是模型实现）。
